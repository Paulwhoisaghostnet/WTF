## Puppet Retest Snapshots

The retest surface relates the beta shell back to the production scan. For every persistent puppet, the beta page compares production-baseline timing with beta timing for understanding, first success, tool discovery, people discovery, activity discovery, and next-step discovery. The relationship purpose is evidence: keep the beta grouping only when these journey measures improve.

## Puppet Memory Ledger

The memory ledger relates each persistent puppet back to the next beta decision. It gathers first task, success condition, six checkpoint outcomes, confusion, hesitation, dead-end note, abandonment risk, success, delight, unexpected discovery, remaining friction, next route, and saved time so the next UI/UX loop starts from observed puppet evidence instead of scattered notes.

## Policy

Assume every app has value. Before hiding any app, beta must attempt better grouping, explanation, routing, and visibility. Hiding remains a last resort after validation.

## The Count Command Deck

The beta hub now maps admin liveops into six command cards: first-quest triage, challenge arcs, reward economy tuning, role/permission review, market management, and abuse-loop audits. Each command stays a route into existing gated WTFOS surfaces and records trigger, admin action, player outcome, audit proof, and risk control.

The Count summary cards add a read-only management scan over the same admin relationships: user needs, role gates, quest/challenge load, reward settlement, market operations, and automation definitions. The cards do not create a new admin surface; they route back to `/admin` and rely on existing `/api/admin/*` permission checks.
