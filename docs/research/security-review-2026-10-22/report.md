# WTF security announcement review — October 22, 2026

**The highest-priority exposure is the Node runtime used by the live app's build configuration.** Its immutable image contains Node 22.23.1, and the application accepts Brotli request bodies before authentication. The October 21 Node update fixes a Brotli decoder RCE. The desktop runtime, relay compiler and MCP integration also need attention. No evidence of compromise was sought or established.

**Review contract:** identify announcements from October 19–22, 2026 (America/Los_Angeles), include relevant adjacent disclosures and newly indexed older advisories with their actual dates, compare affected versions and prerequisites with WTF, and distinguish deployed-source evidence, local dependencies, conditional exposure and non-applicability. This is a report, not a remediation or penetration-test pass.

**Evidence boundary:** the public health endpoint reported commit `bf2a5bc639196dbc062efabf9709afb2ab53dfaf` at `2026-10-22T19:31:06.974Z`. That exact commit exists locally and was inspected separately from the dirty working tree (`HEAD f4e26986`). Anonymous OCI registry metadata resolves the source-pinned image digests to versions. No running-container binary inventory or privileged host inspection was performed. A health response plus source configuration does not independently attest the running image. Public PDS, social, moderation and relay health endpoints responded, but do not disclose reliable runtime versions. [Saved runtime evidence](evidence/wtf-runtime-evidence-20261022.json).

**R01 source proof:** live `Dockerfile:1,39` pins digest `6c74791e…` → OCI `NODE_VERSION=22.23.1`. Live `server/app.ts:317,323` installs `express.json` / `express.urlencoded`; auth is at `:406`, CSRF at `:408`. Current checkout equivalents are `server/app.ts:386,392,475,477`. Installed `body-parser/lib/read.js:222–224` invokes `zlib.createBrotliDecompress()` for `Content-Encoding: br`; neither parser sets `inflate: false`. Caddy configuration does not reject this encoding. This establishes source-level reachability, not successful RCE through the live edge. [Live app source snapshot](evidence/live-server__app.ts), [live Dockerfile](evidence/live-Dockerfile).

**R05 source proof:** live `server/lib/wtf-mcp.ts:715` constructs the server; `:971,1042` accept query records and `:2727` accepts an array without an element-count bound. Live `server/routes/mcp.ts:294` authenticates the token, and `:445` passes already-parsed `req.body` to the SDK. Existing byte and rate limits do not demonstrate protection against the advisory's validation amplification. An OOM/crash was not attempted. [Live MCP server](evidence/live-server__lib__wtf-mcp.ts), [live MCP route](evidence/live-server__routes__mcp.ts).

## Remaining uncertainty and scope exclusions

- **Running binaries:** establish `process.versions`, image IDs/digests and `go version -m` from the deployed environment when remediating. Public liveness is not patch evidence. Confirm desktop download contents separately.
- **OS/native libraries:** the Dockerfile installs curl, ffmpeg, Python, CA packages and Chromium, but its source does not establish installed package revisions. No specific Linux kernel, OpenSSL OS package, ffmpeg or mailserver CVE is assigned from age alone. The PostgreSQL image resolves to 16.14; no October 19–22 PostgreSQL match was established.
- **Other hosts:** Kiln, native signer/bot services, separately hosted Collekt, third-party services and host kernel/package state were not comprehensively inventoried. No universal “WTF is safe” conclusion follows from this report.
- **Excluded work:** no application/lockfile fixes, installs, migrations, exploit traffic, commits, pushes or deployments. No interaction changed, so E2E inventory updates and behavioral test runs were not necessary for this report. Only evidence/report artifacts and required bounty tracking were written.

Recommended implementation order follows the concrete attack surfaces: replace the app/PDS Node runtimes; refresh network-capable desktop and relay runtimes; enable MCP validation safeguards; preserve live dependency fixes while reconciling the working tree. Each remediation should verify its actual running/distributed artifact rather than just a manifest or successful build.
