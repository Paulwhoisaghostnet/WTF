Electron 43.8.3 addresses the compromised certificate-authority issue [GHSA-jr5w-w6x2-84p9](https://github.com/electron/electron/security/advisories/GHSA-jr5w-w6x2-84p9). Its [published runtime versions](https://releases.electronjs.org/release/v43.8.3) still embed Node 24.22.0. This release is **not** an attestation of the Node 24.22.1 fixes in the [October Node security release](https://nodejs.org/en/blog/vulnerability/october-2026-security-releases). The audited production desktop entry points do not use Node HTTP/2, Brotli decompression, outbound Node fetch/HTTPS/DNS, or archive extraction; their loopback HTTP handlers buffer raw request bodies and parse JSON. Renderer networking uses Chromium with sandboxing enabled and Node integration disabled. No affected embedded-Node API path was demonstrated reachable in these apps. Upstream embedded-Node backports remain a documented runtime caveat.

No compatible patched resolution was available in the audited graph. The suggested `electron-builder` 26.5.0 would downgrade the working 26.15.3 packager, so no forced audit downgrade was applied. These dependencies are excluded from packaged application files; see [desktop-build-audit-residuals.json](desktop-build-audit-residuals.json).
