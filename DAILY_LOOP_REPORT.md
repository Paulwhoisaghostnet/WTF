# WTFOS Beta Daily Loop Report

Date: 2026-06-23

Users return when WTFOS can answer: what changed, who moved, what can I finish, what did I earn, and what unlock is next.

| Loop | Apps | Why it works |
| --- | --- | --- |
| Check what changed | Notifications, Mission Control, Digest | Explains replies, rewards, rooms, publish states, and system work. |
| Complete one quest | Side Quests, Challenges, Leaderboards | Converts discovery into EXP, rewards, and visible progress. |
| See people moving | W Feed, Skywire, WTF LIVE, Leaderboards | Makes other people active and visible. |
| Find one object | Gallery, Rat Race, Hoard | Gives collectors and curators a changing reason to browse. |
| Move one project forward | Studio, Broot, Macaroni, IPFS Pinning, WTF Domains | Gives creators an incremental publishing path. |

The beta discovery trails now make those loops explicit on `/beta`: public now signals lead into role-specific next steps, protected routes explain which signed-in surface owns the action instead of bypassing auth, every non-public trail step names what the gate protects, and per-trail live snippets show the proof in the path where it matters. WTF LIVE room presence, upcoming calendar events, WTF TV channel listings, public trade-board objects, and public XP activity now give the daily loop more social/time/media/collector proof before sign-in.

The First-Minute Wayfinder makes the daily loop reachable sooner. A returning user can jump directly to people now, object hunt, creator runway, builder output, the atlas, or Count review instead of scrolling through every beta board to remember where the next action lives.

The Section Compass makes the expanded daily loop easier to revisit. A returning user can jump directly to now signals, people discovery, attention triage, daily return, progression boards, relationship boards, puppet paths, The Count runbook, or the atlas using only beta-local hash and scroll state.

The puppet retest snapshots make the daily loop measurable. Each persistent agent shows production-baseline time versus beta time for understanding WTFOS, first success, useful-tool discovery, people discovery, activity discovery, and next-step discovery. This gives the beta team a daily signal for whether the shell is improving real journeys or merely adding more surface area.

The Daily Return Board turns the report into an early `/beta` action surface. It maps six return choices to existing routes: check what changed in Notifications, complete one quest through Side Quests, see people in W/LIVE/WIM, find one object from Gallery/market context, move one project through Studio and creator tools, or review one Count/admin queue through Admin. Each card states what to do today, why to return tomorrow, what progression hook it uses, what visible proof supports it, and what The Count controls when it becomes liveops work.

The Unlock Passport turns the daily loop into progression memory. Each puppet gets one card that says what is visible now, what safe action to take, what proof is needed, what unlocks next, what remains locked, what The Count reviews, and why to return tomorrow. This keeps daily side quests and challenges understandable without implying that EXP, levels, roles, rewards, market sinks, wallet actions, or admin authority changed from beta.

The Unlock Questline Board deepens the daily quest loop. It shows how a daily action can become a larger unlock path through existing side quests, challenges, EXP, rewards, role/permission readiness, and Count review. This helps users understand the game without relying on an assistant, and helps admins understand which route owns the next review.

The Unlock Governance Matrix makes the admin daily loop safer to operate. It tells The Count which evidence proves readiness, how EXP should be interpreted, which reward or market sink may be affected, where role authority stops, and which anti-farm guard needs review before a loop is promoted.

The App Relationship Navigator makes daily handoffs clearer. Returning users can see whether today's action belongs in the first-win, collector, creator, builder, curator, community, economy, or Count liveops chain, then follow existing route buttons from what comes before to what should happen next.

The Count Admin Workbench turns that daily review into eight existing-route jobs: triage a user need, create a side quest, create a challenge arc, configure a reward, review a role or app gate, manage a market sink, audit automation, or review visibility. Each card keeps the management action tied to existing admin routes, player routes, proof, checklists, decision gates, and risk controls, so daily tuning stays auditable.

The Count Liveops Recipe Board turns daily tuning into six rollout scans: starter witness, creator publish, collector market, builder surface, curator signal, and community return. Each recipe names the EXP interpretation, side quest, challenge, reward, role or permission boundary, market or notification effect, anti-farm rule, player return reason, and six existing route stages, so The Count can plan tomorrow's unlock pressure without beta writing admin state.

The Public Proof Board adds a faster daily scan for returning anonymous or signed-out users: a fresh object to inspect, a creator channel to watch, a playable project to try, and a builder output route to follow when existing public data is available. Quiet proof cards explain that the route is still valid and can be checked again later.

The People Discovery Board adds a social daily scan: active users, new users, creators, collectors, builders, curators, collaborators, and interesting wallets. Each role has proof signals, next action, and quiet fallback, so a returning user can decide whether to look at people, objects, projects, live rooms, or wallets without waiting for a notification.

The Route Group Guide adds a daily orientation scan for overlapping tools. A returning user can quickly tell whether today's work belongs in the first-win, collector economy, creator pipeline, builder output, curator signal, community comms, or Count liveops cluster, then open the existing owner route or filter the atlas without changing app behavior.

The Attention Triage Board turns that scan into seven route-owned decisions: first safe action, people moving now, collector heat, creator recovery, play/builder output, tomorrow catch-up, and Count hot queue. Each card shows live/protected/quiet proof signals, a next action, a quiet fallback, and The Count control note without creating notifications, rewards, roles, or assistant behavior.

Each trail also has a state readout so a quiet public signal, a protected signed-in step, an unavailable public provider, and an admin-only operation do not all feel like the same dead end. This makes return timing clearer: quiet data says check again later, protected data says sign in, unavailable data says keep the route path, and admin-only data stays with The Count.

The Social Pulse now groups return-loop events by reason to care: social attention, progress and unlocks, live and scheduled moments, creator recovery, collector and market motion, and Count admin attention. This makes "what changed?" easier to scan without changing notification delivery or preferences.

The Notification Control Map now turns each return-loop group into a manageable user-control path: act in the owning route, tune delivery in System Settings at `/settings`, catch up from Digest at `/digest`, and keep `/api/notifications/preferences` as the existing preference contract. This gives daily return loops clearer agency without adding a second notification system.

The communication map makes the social daily loop manageable: W Feed shows public motion, WIM captures direct follow-up, WTF LIVE creates time-bound presence, Digest recaps what changed, Mail handles slower private coordination, and Skywire broadcasts important moments outward.

The Count liveops command deck makes the admin daily loop manageable without exposing hidden power: triage first quests, create challenge arcs, tune rewards, review permissions, manage market availability, and audit farmable loops from existing gated surfaces.

The Count admin summary cards give the admin puppet a daily first scan: which users may need help, which role gates exist, how many side quest/challenge definitions are loaded, whether rewards are unsettled, how much market admin state exists, and which automation definitions need review. Non-admin users see locked cards instead of hidden counts.

Admin-only operations, operator wallet, contract factory, backup manager, recovery tools, and deep permission surfaces should stay hidden until explicit admin need. EXP can signal readiness for creator or economy paths, but it must never grant admin authority by itself.
