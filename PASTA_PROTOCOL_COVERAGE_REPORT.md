## Risk Areas

- Wallet/network drift between Macaroni's proven legacy RPC defaults and new Pasta AGENTS.md defaults.
- Trusted-creator wtfOS pinning/hosting accidentally leaking into standalone builds.
- Treating Pasta pin-record shape validation as live provider durability; the live provider, PDS publication, object-store write, and recovery-drill boundary remains open.
- Treating the local WTF.ME host-mapped proof or a TLS-allowed unrelated production user site as Pasta production readiness; the actual Pasta host must pass `npm run pasta:wtfme:live-check` after an intentional publish.
- Public hosting falsely reporting live before WTF.ME serves the expected page on the actual production host; local host-mapped proof is necessary but not sufficient.
- Indexer lag or high-level token endpoint omissions causing operation hashes to be mistaken for full ownership/metadata proof; fresh Shadownet contracts should verify storage and big-map state directly when needed.
- Gnocchi/open-edition proof mints should use a tiny nonzero price, because zero-price mints can trigger an empty treasury transaction failure even when the rest of the open-edition setup is valid.
- Colander signed actions must keep adapter detection, network-specific explorer routing, metadata decoding, and chain preflight in lockstep before any browser-wallet mutation is claimed.
- Marketplace previews hiding edition quantity, owner, price, or target contract.

## Recommended Implementation Order

1. Keep Macaroni unchanged and lock naming tests.
2. Implement or verify shared Pasta package, metadata, relationship, and adapter helpers.
3. Complete CH-EASE target-aware package export and handoff validation.
4. Complete Spaghetti because it anchors standard collection/token-product publishing.
5. Use `npm run pasta:wtfme:live-inventory` to identify a registered, TLS-allowed, owner-accessible production host, use `npm run pasta:wtfme:live-publish` to publish the proven Pasta pages to that eligible real `*.wtfos.me` host, then make `PASTA_WTFME_LIVE_HOST=<published-host> npm run pasta:wtfme:live-check` pass before signed mint/purchase validation.
6. Promote wtfOS artifact/metadata pinning from record-shape proof to live provider/PDS/object-store durability plus recovery drill.
7. Prove Colander browser-wallet mutation and post-operation refresh if signed management remains in the first release boundary.
8. Keep Macaroni and Pasta Suite installer verifiers as release gates while adding any future standalone Pasta installers.
9. Use `.agents/docs/live/PASTA_LIVE_READINESS_MATRIX.md` as the live-push checklist, then only after production hosted-page, pinning/recovery, and signed-management boundaries are resolved, plan mainnet/full-send deployment work.
