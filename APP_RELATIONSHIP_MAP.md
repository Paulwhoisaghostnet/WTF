## Beta Discovery Trails

| Trail | Existing route sequence | Why it exists |
| --- | --- | --- |
| Collector | `/leaderboard` -> `/gallery` -> `/marketplace` -> `/rat-race` -> `/wtfiam` | Connect public holder, listing, trade-board, and market-heat proof to signed-in market context, urgency, inventory, and rewards. |
| Creator | `/studio` -> `/tools/broot` -> `/tools/macaroni` -> `/ipfs-pinning` -> `/skywire` | Show the order from workspace to asset prep, packaging, publishing, promotion, and creator/media proof. |
| Builder | `/game-studio` -> `/map-lab` -> `/console` -> `/arcade` -> `/w` | Turn experiments into mapped, testable, playable, discussable projects with console/arcade/feed proof. |
| Community | `/leaderboard` -> `/arcade` -> `/w` -> `/live` -> `/notifications` | Move from public profile activity to shared play, social context, live rooms, and return loops. |
| The Count | `/leaderboard` -> `/side-quests` -> `/challenges` -> `/wtfiam` -> `/admin` | Start admin review with visible reward outcomes before touching quests, challenges, economy, operator tools, or audit commands. |

The Puppet Retest Snapshot layer sits beside these trails and compares production-baseline timing with beta timing for each persistent agent. It does not add a new app relationship; it proves whether the relationship map is improving the requested time-to-understand, first-success, tool-discovery, people-discovery, activity-discovery, and next-step measures.

The Puppet Memory Ledger sits beside the retest snapshots as the persistent-agent memory layer. It does not add a new app relationship; it records each puppet's task, success condition, checkpoint outcomes, confusion, hesitation, abandonment risk, delight, unexpected discovery, remaining friction, next route, and saved-time evidence so the next relationship or navigation improvement starts from observed friction.

The Count command deck adds six admin route relationships over the same existing surfaces: first-quest triage, challenge arcs, reward economy tuning, role/permission review, market management, and abuse-loop audits. The Count summary cards add a strict-admin readout across users, role gates, quest/challenge load, reward settlement, market operations, and automation definitions without creating a new authority path.

Trail state readouts now sit between proof snippets and route steps. They do not create new app relationships; they clarify whether the next relationship is quiet, protected by sign-in/role, temporarily unavailable through a public provider, or strict-admin-only.

The Public Proof Board sits before the role trails and composes existing now-signal sources into four relationships: trade-board/market rows to Gallery, TV channel rows to WTF TV, Arcade discovery/recent play to Arcade, and Console discovery to Console. It adds no app behavior; it makes the current relationship legible.

The People Discovery Board sits after public proof and before attention triage. It groups existing now signals into active users, new users, creators, collectors, builders, curators, collaborators, and interesting wallets. It adds no social graph behavior; it explains who the signals represent, why the user should care, what to open next, and what route remains useful when data is quiet.

The Attention Triage Board sits after public proof and before daily return. It maps first safe action, people moving now, collector heat, creator recovery, play/builder output, tomorrow catch-up, and Count hot queue to existing owner routes while showing live/protected/quiet proof and a quiet fallback. It adds no notification delivery, assistant logic, reward settlement, role grants, or admin authority.

The Daily Return Board sits between proof and trails. It turns six return questions into existing-route relationships: Notifications for changes, Side Quests for one manageable completion, W Feed for active people, Gallery for object discovery, Studio for project recovery, and Admin for Count-only liveops review.

The Unlock Passport Board sits between daily return and questlines. It gives New Tezos User, Collector, Creator, Builder, Curator, Community Member, and The Count one compact route relationship each: primary action, proof route, next route, related routes, what unlocks, what stays locked, Count review, and return-tomorrow reason. It adds no route behavior or progression state.

The Unlock Questline Board sits between the daily return layer and role trails. It makes side quests, challenges, EXP, rewards, roles, permissions, Count review, and abuse guards legible as seven existing-route paths without changing any progression behavior.

The Unlock Governance Matrix sits immediately after the questline board. It converts each route-owned path into a Count-readable review contract: evidence, EXP signal, reward or market sink, role boundary, Count decision, and anti-farm guard.

The App Relationship Navigator sits immediately after governance and before the role trails. It adds eight explicit handoff chains: first safe win, collector context, creator publish, builder output, curator signal, community presence, economy spend, and Count liveops. Each chain states what comes before, what the route consumes, what it feeds into, what comes after, what The Count watches, and the existing routes that carry the handoff.

The Route Group Guide sits immediately after the App Relationship Navigator and before the role trails. It adds seven clarification clusters: first win, collector economy, creator pipeline, builder output, curator signal, community comms, and Count liveops. Each card explains what to use first, what to use next, which proof matters, what quiet data means, what The Count watches, and which App Visibility Atlas filter should be applied. It changes only beta navigation and filter state.

The Count Admin Workbench sits inside The Count section after live admin summary counts. It maps user triage, sidequest creation, challenge creation, reward configuration, role/app-gate review, market sink management, automation audit, and visibility review to existing admin routes, player routes, checklists, proof, risk controls, and success signals without creating a new write path.

The Count Liveops Recipe Board sits immediately after the Count Admin Workbench. It converts starter witness, creator publish, collector market, builder surface, curator signal, and community return needs into six route-owned rollout recipes across existing EXP, side quest, challenge, reward, role/permission, market, notification, and app-gate surfaces. It changes only beta guidance; recipe stage buttons open existing routes through their current gates.

The Journey Command Center sits inside Puppet Paths as the selected persona's compact action stack. It does not add a new route or app; it selects existing proof, action, proving, return, and Count review routes so the user can move without cross-reading every board.

The Notification Control Map sits after Social Pulse and before the communication map. It connects every notification relationship to an action route, System Settings at `/settings`, Digest at `/digest`, and the existing `/api/notifications/preferences` contract without creating a new notification authority.

The App Visibility Atlas sits after the liveops command deck as the final catalog review layer. It filters the same route catalog by search, tier, stage, and puppet path so reviewers can validate grouping and routing before any app is hidden, relabeled, or moved to a lower-visibility tier.

The First-Minute Wayfinder sits immediately after the hero and before live proof. It does not create a new app relationship; it chooses which existing relationship layer to reveal first and applies beta-local persona or atlas filters when useful.

The Section Compass sits immediately after the Wayfinder and before live proof. It does not create a new app relationship; it gives the now-larger beta shell fourteen section anchors so users and The Count can jump to the relationship layer they need before scrolling through every board.
