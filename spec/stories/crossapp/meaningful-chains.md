# Cross-App User Stories: Meaningful Chains

These chains cover the product paths users are expected to run end to end.

## CH-EASE -> Tortellini blocked example

As a Creator
I want a CH-EASE package that names Tortellini to be rejected as an unknown Pasta target
So that new developers understand Tortellini is not a current product and must not be implemented by accident.

Acceptance Criteria:

Given CH-EASE has produced a valid package
When the creator selects or imports a target named Tortellini
Then the suite reports that Tortellini is intentionally absent, preserves the package for another valid target, and records no route, app dossier, contract, or implementation requirement for Tortellini.

Failure Criteria:

- Any generated Tortellini tool route, app dossier, contract artifact, or deployment story is a naming-model failure.
- If an owner later approves Tortellini, the app dossier, feature specs, directed pairs, lifecycle stories, adversarial tests, and E2E stories must be regenerated before code.

## CH-EASE -> Macaroni -> WTF.ME Hosting

As a Creator
I want to move work through CH-EASE -> Macaroni -> WTF.ME Hosting
So that the resulting token, contract, hosted page, or management surface remains coherent across apps.

Acceptance Criteria:

Given each previous step has produced a validated durable artifact
When the creator opens the next app or service in the chain
Then the next step imports the artifact, preserves CIDs/KT1s/relationship metadata, shows missing requirements, and produces its own validation evidence.

Failure Criteria:

- If any step fails, the chain report names the failing app/service and the last durable artifact.
- A later app may not silently reinterpret token products as contract products, or vice versa.

## Macaroni -> Gnocchi -> Ravioli

As a Creator
I want to move work through Macaroni -> Gnocchi -> Ravioli
So that blind-drop outputs, open-edition editions, and bundle wrapping can be reasoned about as distinct token-product layers.

Acceptance Criteria:

Given Macaroni has produced a valid token product with media, metadata, contract address, and wallet/network proof
When the creator uses Gnocchi to configure an edition path and Ravioli to wrap or group the resulting token references
Then every step preserves CIDs, KT1s, token ids, edition supply rules, bundle membership, relationship metadata, and the last durable artifact for recovery.

Failure Criteria:

- Gnocchi may not reinterpret Macaroni blind-mint state as an open edition unless the creator confirms the edition model and supply semantics.
- Ravioli may not bundle unresolved token references, hidden supply constraints, or wallet-operation hashes that are not node/indexer-visible.
