# WTFOS Beta Migration

Date: 2026-06-24

## Migration Status

Not ready for production migration yet. The beta shell is still an independent UI/UX evolution layer.

## Migration Gates

Before any production migration recommendation:

- New users answer all first-minute questions under 60 seconds.
- Creators discover creation tools without help.
- Collectors discover collection tools without help.
- Users discover active people without help.
- Users discover active projects without help.
- Users understand app relationships without help.
- Visibility score increases with real production-derived activity data.
- Retention score increases through notifications, quests, live rooms, and project recovery.

## Current Safe Candidate

The `/beta` route itself is safe as an independent beta destination after deployment because it preserves production routes and only links to existing surfaces through their existing gates. The First-Minute Wayfinder is migration-safe because it only jumps within the beta shell, selects puppet context, adjusts beta-local atlas filters, and links to existing routes through their current gates. The Section Compass is migration-safe because it only maps fourteen existing beta board anchors, updates the beta-local URL hash, and scrolls inside `/beta` without opening apps, changing filters, writing user state, creating assistant behavior, or bypassing gates. The public proof board uses existing read-only public trade-board, marketplace, TV channel, Arcade discovery/recent play, and Console discovery reads; beta avoids auto-fetching the profile endpoint that emits profile-view events. The Attention Triage Board is migration-safe because it only composes existing signal readouts into route-owned next-action cards; it does not create notifications, save preferences, settle rewards, grant roles, or bypass public/session/admin gates. The Daily Return Board is migration-safe because it turns retention into route cards for existing changes, quests, people, object, project, and admin surfaces without adding scheduling, reward, notification, or permission logic. The Unlock Passport Board is migration-safe because it makes visible-now, next-safe-action, proof-needed, unlocks-next, stays-locked, Count-review, and return-tomorrow context readable for each puppet without creating progression state, granting roles, settling rewards, changing market state, or bypassing gates. The Unlock Questline Board is migration-safe because it explains sidequest/challenge/reward/role/admin relationships and stage-links existing routes, but it does not create quest definitions, settle rewards, grant roles, write permissions, or alter admin review behavior. The Unlock Governance Matrix is migration-safe because it only documents evidence, EXP interpretation, reward/market sinks, role boundaries, Count decisions, and anti-farm guards around existing routes; it does not create a progression engine, alter automation, settle rewards, change permissions, or grant admin authority. The App Relationship Navigator is migration-safe because it only explains existing route chains, access hints, before/after context, consumed inputs, outputs, and Count-watch rules; it does not rewrite apps, alter app purpose, add APIs, or bypass public/session/role/admin gates. The Count Admin Workbench is migration-safe because it maps admin jobs to existing admin and player routes, evidence, checklists, decision gates, risk controls, and success signals without writing sidequests, challenges, rewards, roles, market items, automation, notification preferences, or app gates from beta. The Journey Command Center is migration-safe because it only narrows the selected puppet path into five existing route-owned buttons and leaves every route's current public, session, role, or admin gate in charge. The App Visibility Atlas filters are migration-safe because they only narrow the beta-local catalog view by search, tier, stage, and puppet path; they do not hide production routes, mutate app gates, or alter feature availability. The communication map is migration-safe because it only explains and routes to existing W Feed, WIM, WTF LIVE, Digest, Mail, and Skywire surfaces. The notification control map is migration-safe because it only points to existing action routes, System Settings `/settings`, Digest `/digest`, and `/api/notifications/preferences`; it does not create delivery logic or write preferences. The puppet retest snapshots are migration-safe because they are beta evidence/readout data only and do not alter the puppet harness, route behavior, or production telemetry. The per-trail proof snippets, trail-level state readouts, protected-step gate explanations, grouped Social Pulse return loops, Count command deck, and Count admin summary cards are also migration-safe as beta navigation/runbook layers over existing public, session, and admin gates.

The Puppet Memory Ledger is migration-safe because it renders existing beta puppet evidence in one place: task, success condition, checkpoint status, confusion, hesitation, abandonment risk, delight, unexpected discovery, remaining friction, next route, and saved-time readout. It does not create persistent production agents, write user state, alter the puppet harness, or change any route, reward, role, notification, admin, wallet, database, API, contract, or app behavior.

The People Discovery Board is migration-safe because it groups existing beta now signals into role-based cards and only opens current WTFOS routes through their existing access gates. It does not create a new social graph, write profile-view events, follow users, send messages, create rooms, change notifications, alter W/WIM/WTF LIVE/Skywire behavior, or bypass session, role, wallet, admin, API, database, or contract authority.

The Route Group Guide is migration-safe because it only names overlapping route clusters, renders explanation copy, opens existing route buttons through current gates, and applies beta-local App Visibility Atlas filters. It does not hide routes, relabel production apps, change app purpose, write catalog state, grant roles, settle rewards, change notification preferences, or alter admin, API, wallet, database, contract, or app behavior.

The Count Liveops Recipe Board is migration-safe because it only turns user needs into admin-readable blueprints over existing route stages. It does not create side quests, challenges, rewards, roles, permissions, market items, notifications, app gates, automation, SystemEvents, wallet actions, database rows, API contracts, or contract operations from beta.
