# WTFOS Beta Audit

Date: 2026-06-24

Scope: beta UI/UX shell only. Production `wtfos.app` was observed read-only. No app purpose, app logic, contract logic, wallet logic, database structure, API contract, or production behavior was changed.

## Production Scan

- Source: `https://wtfos.app`
- Mode: read-only
- Public root: SPA shell titled `wtfOS`
- Access manifest: canonical origin is `https://wtfos.app`
- Browser routes: 64
- API routes: 78
- Desktop app gate entries: 27
- Enabled desktop apps: 26
- Disabled app gate: `crp-nominations`

## Highest Friction

Production exposes many useful routes, but a new user can still experience the ecosystem as app-name guessing. The highest beta friction is visibility: people, current activity, active projects, market motion, events, and collaboration opportunities are not obvious soon enough.

## Executed Improvement

Corrected the second beta first-impression failure: the page no longer immediately spills into an encyclopedia of boards after the hero. `/beta` now keeps the first viewport action-led with a compact Play/People/Return loop inside the hero and a beta-only playable desk between the hero and deeper evidence. The desk shows the selected quest, proof route, return route, EXP progress, five world lanes for quest/people/discovery/tomorrow/Count, visible 60-second answers, and an explicit "Open research deck" control. The deeper Wayfinder, Section Compass, reports, app maps, puppet evidence, Count runbooks, atlas, and simulated critic gate now sit behind a collapsible Research Deck so human users begin with action and admins can still open the full audit map when needed.

Corrected the beta first impression away from encyclopedia/report density and into a product-home experience. `/beta` now opens with a dark visual hero that frames WTFOS as a playable Tezos world, a role picker, a selected EXP level/passport/questline card, a five-step quest-stage ribbon, one selected next move, proof and return routes, live public-signal counts, mobile fast-start actions, and six compact launch actions before the deeper wayfinding, reports, maps, governance, and atlas surfaces. The 60-second answer strip and simulated 5/5 A+ critic gate are demoted below the launch actions so the first screen leads with action and progression instead of reading like a report.

Added a beta-only persistent agent loop, puppet retest snapshots, visibility radar, route bridge layer, read-only now-signal strip, First-Minute Wayfinder, public proof board, Creator Project Proof Ladder, Attention Triage Board, Daily Return Board, Unlock Passport Board, Unlock Questline Board, Unlock Governance Matrix, App Relationship Navigator, role-based discovery trails, per-trail live proof snippets, trail-level state readouts, protected-step microcopy, Journey Command Center, communication map, notification return-loop groups, notification control map, The Count liveops command deck, strict-admin Count summary cards, Count Admin Workbench, Count Liveops Recipe Board, and a filterable App Visibility Atlas to `/beta`. These surfaces organize existing routes and apps into clearer journeys without changing app behavior or API contracts. The Wayfinder compresses eight common first-minute questions into existing section jumps, selected puppet paths, route-owned destinations, and atlas filters. The retest snapshots compare production-baseline puppet timings to beta timings across all six requested discovery checkpoints. The read-only strip now includes public WTF LIVE room presence, upcoming calendar events, public WTF TV channel signals, public trade-board objects, and public XP activity in addition to leaderboard, reward, market, arcade, and console signals. The public proof board composes those existing public reads into object, creator-channel, playable-project, and builder-output snippets before users choose Gallery, TV, Arcade, or Console. The Creator Project Proof Ladder separates visible proof from signed-in inspection and role-gated proof across Studio, Broot, Macaroni, IPFS Pinning, TV, Console, and Skywire before beta recommends a specialized creator route. The Attention Triage Board turns public, protected, and admin-gated signals into seven route-owned next actions for first safe action, people moving now, collector heat, creator recovery, play/builder output, tomorrow catch-up, and Count hot queues. The Daily Return Board maps changes, quests, people, objects, projects, and Count/admin queues to existing routes while preserving current access gates. The Unlock Passport Board gives each puppet plus The Count one compact visible-now, next-safe-action, proof-needed, unlocks-next, stays-locked, Count-review, and return-tomorrow readout before the deeper questline/governance boards. The Unlock Questline Board turns side quests, challenges, EXP, rewards, roles, permissions, Count review, and abuse guards into seven existing-route progression paths. The Unlock Governance Matrix maps those paths to evidence, EXP signals, reward or market sinks, role boundaries, Count decisions, and anti-farm guards so admins can manage the game without making EXP into authority. The App Relationship Navigator maps first-win, collector, creator, builder, curator, community, economy, and Count liveops chains to comes-before, consumes, feeds-into, comes-after, Count-watch, and existing route-step handoffs. The Count Admin Workbench maps user triage, sidequest creation, challenge creation, reward configuration, role/app-gate review, market sink management, automation audit, and visibility/communication review to existing admin routes, player routes, evidence, checklists, decision gates, risk controls, and success signals. The Count Liveops Recipe Board turns starter witness, creator publish, collector market, builder surface, curator signal, and community return needs into six non-writing blueprints across existing EXP, side quest, challenge, reward, role, market, notification, and app-gate surfaces. The Journey Command Center stitches each selected puppet's proof route, first action, proving route, return route, and strict-admin Count review into five existing route-owned steps so users do not have to assemble the path across separate boards. The App Visibility Atlas now filters the complete beta catalog by search, visibility tier, user stage, and puppet path before any hiding decision, keeping the "explain, group, route, and surface first" policy inspectable. The notification control map points to existing action routes, `/settings`, `/digest`, and `/api/notifications/preferences` without reading or writing preference state from beta. The Count summary cards only read existing `/api/admin/*` endpoints after the current session already passes existing admin gates.

Added a Puppet Memory Ledger to `/beta` so each persistent puppet's first task, success condition, six checkpoint results, confusion, hesitation, dead-end note, abandonment risk, success, delight, unexpected discovery, remaining friction, next route, and saved-time evidence are visible in one place. This is a beta evidence surface only; it does not create a new assistant, replace navigation, persist user state, or change puppet/test execution.

Added a People Discovery Board to `/beta` so users can see active users, new users, creators, collectors, builders, curators, collaborators, and interesting wallets as human roles with proof signals, why-care copy, next actions, quiet fallbacks, and related existing routes. This is a beta visibility/navigation layer only; it does not create social graph logic, write profile views, change W/WIM/LIVE/Skywire behavior, or bypass route gates.

Added a People Proof Gap Matrix to `/beta` so the social visibility priority stays actionable instead of becoming vague. Each role now shows direct/routed/weak proof status, current proof, current weakness, next beta UI move, quiet fallback, and the no-write boundary before opening an existing proof route.

Added a Creator Project Proof Ladder to `/beta` so creators can distinguish public creator/channel/output proof from private Studio/Broot/IPFS inspection and role-gated Macaroni packaging. This is beta dependency guidance only; it does not read private drafts, create assets, pin media, package drops, grant roles, or publish.

Added a Route Group Guide to `/beta` so overlapping app clusters are named before users reach the full atlas: first win, collector economy, creator pipeline, builder output, curator signal, community comms, and Count liveops. Each group explains what to use first, what to use next, which proof to look for, what quiet data means, what The Count watches, and which existing route buttons carry the handoff. This is beta terminology/navigation only; it does not add routes, change access gates, write preferences, grant roles, settle rewards, or alter any app logic.

Added a Count Liveops Recipe Board to `/beta` so The Count can translate user needs into starter, creator, collector, builder, curator, and community unlock blueprints. Each recipe names how EXP should be interpreted, which side quest and challenge shape the loop, where rewards and role/permission boundaries sit, which market or notification effect is allowed, which six existing route stages carry the work, and why beta must not write admin state.

Added a Beta Section Compass to `/beta` after the First-Minute Wayfinder so users and The Count can choose among fourteen major beta boards by question, audience, stage, access boundary, use-when guidance, proof rationale, and next move. It changes only beta-local hash and scroll state; it does not open production apps, alter atlas filters, create assistant behavior, write user state, or bypass any route gate.
