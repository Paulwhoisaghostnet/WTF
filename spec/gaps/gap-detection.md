# Gap Detection

## Unimplemented Features

- Some Pasta surfaces are present as static or planned tools; implementation depth varies by app. The story suite treats missing behavior as a validation gap for later coding passes, not as permission to change code during this documentation loop.
- Tortellini is not missing; it is intentionally not a product under the current owner-approved Pasta structure. The `CH-EASE -> Tortellini` example is covered as a blocked-flow validation requirement.

## Unclear Workflows

- Exact mainnet rollout order per contract app remains dependent on Shadownet proof.
- Marketplace integration should stay preview/inspection first until hidden quantity, ownership, and price tests exist per app.
- Downloaded standalone builds need a release artifact checklist proving wtfOS-only providers are stripped.

## Missing User Stories

- No uncovered app-level story groups remain in this generated pass. Future new Pasta apps must add app, feature, individual, pair, lifecycle, adversarial, and E2E rows before implementation.

## Missing Dependencies

- Live puppet AT/Tezos credentials and Shadownet wallet fixtures may be required for deployment tests.
- Indexer availability, pinner provider credentials, and WTF.ME public host readiness must be declared per environment.

## Missing Infrastructure

- A unified executable runner can be added after this spec pass to transform these markdown validation cases into Playwright/API tests.
- Production mainnet deployment tests must wait for Shadownet evidence and operator approval.

## Missing Permissions

- Trusted-creator hosted pinning/hosting must be consistently gated across all Pasta apps.
- Colander action availability is advisory; on-chain permission failures must be represented in UI and tests.

## Missing Ownership Rules

- Relationship metadata is designed but not enforced as a full Wallet -> Franchise -> Collection hierarchy.
- Contract adapters must be expanded whenever a new Pasta contract entrypoint set appears.

## Missing Recovery Paths

- Each generated feature includes last-durable-artifact recovery requirements. Later implementation must wire concrete UI for every CID, op hash, KT1, hosted URL, and package manifest boundary.
